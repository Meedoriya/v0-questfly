# Политика публичного API (v1)

Дополняет [`openapi.yaml`](openapi.yaml) продуктовыми и операционными решениями, которые **не выводятся из кода** однозначно.

## Версия и путь

- Базовый префикс: `/api/v1`. Ломающие изменения: новая мажорная версия пути (например `/api/v2`) либо отдельные эндпоинты, согласованные с клиентами.
- `GET /api/v1/ping` и `GET /health` не версионируются под `/api/v1` (кроме ping).

## Аутентификация

- **Bearer** — access JWT из поля `access_token` в ответе `register` / `login` / `refresh`.
- **Refresh** — ротация: при `POST /api/v1/auth/refresh` выдаётся новая пара токенов; старый refresh в типичном JWT-flow считается недействительным для следующего refresh (см. реализацию `TokenService`).

## Поведение, зафиксированное в коде (важно для UI)

- **`GET /api/v1/auth/me`**: в ответе `token` заполняется **пустыми строками** (не `null` и не отсутствие поля). Клиентам: не ожидать валидные токены в этом эндпоинте; при необходимости продукт может изменить бэк на `null`/omit.
- **`expires_at`**: строка в формате, как в `time.Format` Go (`2006-01-02T15:04:05Z07:00`); **зависит от часового пояса процесса**. Для единообразия в будущем можно договориться о **UTC** и/или нормализовать в коде.
- **Logout / revoke refresh**: в текущем API **нет**; выход = удалить токены на клиенте. Отзыв с сервера — отдельная фича.

## Онбординг и async (202)

- `POST .../generate` и `POST .../next-quest` возвращают **202** с телом `AsyncResponse`; **SLA и таймауты** не нормированы в API — клиент **поллит** согласованные GET (например `current-quest`, `onboarding/.../status`).

## Пагинация

- **`GET /api/v1/campaigns`**, **`GET /api/v1/routines`**: **без** `limit/offset` в v1; возвращается полный набор. При росте объёма — ввод пагинации в новой версии спеки + бэк.

## Ошибки

- Сводка `error.code` в описании `openapi.yaml` (info) и `HttpxErrorBody`. Точная матрица «маршрут → HTTP → code» — по мере надобности расширять в спеке per-operation.
